# 반도체 밸류체인 탭 계획 (2026-11-17 작성)

바이오 탭은 "종목마다 가정치를 관리하고 → 가치를 계산해 → 시총과 견준다"였고,
소비재 탭은 "종목마다 수출 흐름을 관리하고 → 월별 통관으로 분기 매출을 어림한다"였다.
반도체 탭은 **"밸류체인 도식 위에 종목을 앉히고 → 위(수요: 빅테크 AI capex)와 옆(공급: 삼성·하이닉스·마이크론 증설)의 움직임이
→ 전공정·후공정 어느 칸의 수주·매출로 언제 번지는지를 펀더(분기 매출·OP)와 수주 공시로 확인한다"** 이다.
결정이 필요한 곳은 **[결정]**, 실측이 남은 곳은 **[확인 필요]**.

### 데이터 제약 (계획이 여기에 맞춰져 있다)

- 장비 회사의 매출은 **고객 팹 공정의 뒤를 따른다**: 셸 공사 → 클린룸 → 장비 반입(이때 수주·선수금) → 설치·검수(이때 매출) → 양산 램프(이때 소재·부품 소모 증가).
  그래서 증설 '발표'보다 **단계 전환 시점**을 적는 것이 핵심이다. 보도마다 시점이 다르면 둘 다 적고 출처·날짜를 붙인다.
- 수주 공시는 **매출의 10%(대기업 5%) 이상**일 때만 의무다. 작은 수주·큰 회사의 수주는 안 보인다 → '보이는 수주'로만 표시하고, 분기보고서의 **수주잔고 표**로 보완한다.
- 계약상대는 '영업비밀'로 가리는 경우가 많다. 그때는 지역(평택·청주·이천·용인·미국·중국)과 계약 기간으로 고객·팹을 추정하고 '추정'이라고 적는다.
- 삼성·하이닉스는 팹별 capex 를 공시하지 않는다. 분기 현금흐름표의 유형자산 취득(회사 전체)과 사업보고서의 '시설투자' 문단이 공식 숫자의 전부다.

## 1. 밸류체인 도식 (화면 맨 위, SVG)

정적 그림이 아니라 `semi_chain.json` 으로 그리는 SVG 다. 칸마다 종목 수·최근 분기 매출 YoY(중앙값)·최근 수주 건수를 얹고, 칸을 누르면 아래 표가 그 칸으로 걸러진다.

```
[최종 수요] 빅테크 AI capex ─ GPU·ASIC(엔비디아·브로드컴) ─ AI 서버
        │ (메모리·파운드리 주문)
[설계]  팹리스·디자인하우스·IP ───────────────┐
        ▼                                     │
[팹]    메모리: 삼성·SK하이닉스·(마이크론)  │  파운드리: (TSMC)·삼성·DB하이텍
   ▲ 장비·부품 (capex 따라)        ▲ 소재 (가동률·웨이퍼 투입 따라)
[전공정] 증착·식각 │ 세정·열처리 │ 노광 주변·계측·검사 │ 소모 부품(쿼츠·세라믹·SiC 링·파츠 세정)
[소재]  웨이퍼 │ 특수가스 │ 전구체·케미컬 │ 블랭크마스크·펠리클
        ▼ 웨이퍼 완성
[후공정] HBM 적층(TSV·TC 본더·리플로우) │ 테스트(핸들러·번인·테스터) │ 프로브카드·소켓 │ 레이저 그루빙·다이싱
[OSAT·기판] 패키징·테스트 외주 │ FC-BGA·패키지 기판 │ MLB(서버)
```

칸 사이 화살표에 **무엇이 흐르는지**를 적는다: 'capex → 전공정 장비(6~12개월 뒤 매출)', '가동률 → 소재·부품(같은 분기)', 'HBM 캐파 → TC 본더·테스트', '신제품 수 → 프로브카드·소켓'.
이 문장은 `semi_chain.json` 의 `drivers` 에 둔다(§6의 영향 화면이 같은 것을 쓴다).

## 3. 종목 카드 (`semi_assets.json`, 바이오 `bio_assets.json`·소비재 `consumer_assets.json` 자리)

```json
{"code": "042700", "name": "한미반도체", "stage": "후공정 장비", "cell": "HBM 적층·본딩", "also": [],
 "products": ["TC 본더(HBM)", "마이크로 쏘", "비전 플레이스먼트"],
 "customers": [{"n": "SK하이닉스", "share": null, "src": "수주 공시"}, {"n": "마이크론", "src": "수주 공시"}],
 "exposure": {"memory": 0.9, "hbm": true, "foundry": 0.1},
 "moat": [{"t": "HBM TC 본더 SK하이닉스 주력 공급", "kind": "점유율", "src": "2025 사업보고서 '사업의 내용'", "d": "2026-03-18"}],
 "fabs": ["SKH-M15X", "SKH-Cheongju-PKG", "MU-SG-HBM"],
 "reviewed": false}
```

- **해자** 는 종류를 나눠 적는다: 점유율(국내·세계), 독점·단독 공정, 고객 퀄 통과, 기술 장벽(특허·공정 난이도), 전환 비용. 문장마다 **출처와 날짜**를 단다.
  초안은 사업보고서 '사업의 내용'(주요 제품·시장점유율·경쟁 요소 문단)과 리포트 요약에서 뽑고, 화면에 '검수 전'을 표시한다(소비재 매핑과 같은 방식).
- `exposure` 는 부문 매출이 있으면 거기서 계산하고(펀더 seg), 없으면 사업보고서 문장 기준 어림 + '어림' 표시.
- `fabs` 는 §5 증설 트래커의 팹 id. 수주 공시의 지역·계약상대로 자동 제안하고 사람이 확정한다.
- **[결정]** 해자 문장을 누가 쓰나: Claude 초안 → 사용자 검수(권장) / 처음부터 사용자.

## 4. 펀더·수주 연결

### 4.1 펀더 (이미 있는 것)
- 종목 줄: 최근 분기 매출·OP·OPM, YoY, @darthacking 서프/미스, 부문 매출(삼성 DS·하이닉스 제품별 등).

### 4.2 수주잔고 (새로 — 펀더 파이프라인에 토픽 하나 더)
- 장비·부품 회사는 분기보고서 '매출 및 수주상황'에 **수주총액·기납품액·수주잔고** 표를 싣는다. 원문은 `.cache/fund_docs` 에 이미 있다 → 다시 받지 않고 `--reparse` 로 읽는다.

- [확인 필요] 회사마다 표 형식이 달라(품목별·고객별·금액 단위) 성격별 비용 표처럼 열 맞춤이 필요하다. 먼저 장비 15종목으로 맞춰 본다.

### 4.3 수주 공시 이력 (있는 것을 5년으로)
- DART 목록 API 로 대상 종목의 '단일판매ㆍ공급계약체결/해지' 5년치를 받아 `parse_contract` 로 읽는다(1회 약 70종목 × 수십 건).

## 6. 전공정·후공정 영향 보기

밸류체인 도식 아래에 **"지금 무엇이 어느 칸으로 번지는 중인가"** 를 세 가지로 보여 준다.

1. **영향 표** (행 = 사건, 열 = 칸): 예) 'SK하이닉스 M15X 램프'(→ 소재·부품 지금, 후공정 HBM 장비 지금), '삼성 P5 장비 반입 예정 2027'(→ 전공정 장비 수주 2H26~),
   '빅테크 3Q capex +108%'(→ HBM·기판·테스트). 칸마다 근거(최근 2분기 그 칸의 수주 건수·금액, 매출 YoY 중앙값, 서프/미스 수)를 숫자로 붙인다.
   방향·시차는 §1 `drivers` 규칙에서 나오고, 숫자는 실측만 쓴다(예측치 안 만든다).
2. **선행-후행 그래프**: 고객 capex(삼성+하이닉스 유형자산 취득, 빅테크 capex) vs 칸별 매출 합계를 분기로 겹치고, 0~4분기 시차별 상관을 표로(소비재 탭의 수출↔매출 상관과 같은 방식).
   어느 칸이 몇 분기 늦게 따라오는지가 숫자로 나온다.
3. **팹 타임라인**(간트): 팹마다 단계 막대 + 오늘 선 + 그 팹과 연결된 장비 수주 점. 장비 반입이 다가오는 팹과 그 팹에 납품 이력이 있는 종목이 한눈에 보인다.
