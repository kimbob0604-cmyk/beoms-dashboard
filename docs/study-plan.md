## 1. 구조

### 1-1. 자리 — **[결정]** 기존 대시보드 안의 새 탭 (권장)

- `public/study.html` 한 장 + 탭 이름 **"Study"**, 화면 제목은 **Beom's Study**.
- 기존 대시보드 안에 두는 이유: 기업 칩을 누르면 이미 있는 **종목 상세 패널**(`stock.js`)과 **바이오 탭 자산 카드**로 바로 넘어갈 수 있다.
  별도 사이트로 떼면 이 연결을 다시 만들어야 한다.

### 1-2. 분류 트리 (왼쪽 사이드바)

```
Beom's Study
├─ 반도체            (자료 들어오면 채움 — 예: 메모리/HBM, 파운드리, 장비, 소재·부품, 후공정)
├─ 바이오
│   └─ 항암
│       └─ 고형암
│           ├─ 시장 지도: 단일항체 vs 저분자
│           ├─ 면역관문억제제 PD-(L)1
│           │   ├─ 작동 원리·반응 예측
│           │   └─ 적응증별 (흑색종, NSCLC, 신장암, 유방암, 방광암, 기타)
│           ├─ Next PD-(L)1
│           │   ├─ ADC (TROP2 / CLDN18.2 / B7-H3)
│           │   ├─ mRNA 항암백신
│           │   ├─ T세포 인게이저
│           │   └─ PD-1×VEGF 이중항체
│           └─ 저분자 (CDK4/6 유방암, 전립선암, EGFR NSCLC)
└─ 소비재            (자료 들어오면 채움 — 예: 화장품, 음식료, 유통)
```

- 트리는 **주제 기준**이다. 문서 기준이 아니다. 나중에 다른 증권사의 ADC 리포트가 오면 같은 "ADC" 가지에 붙는다.
- 각 노드 화면 위쪽에 "이 주제를 다룬 문서" 목록(출처·날짜)을 단다.

### 1-3. 카드 — 분해의 단위

| 카드 종류 | 내용 |
|---|---|
| **요약** (주제마다 1장) | 이 주제의 핵심 3~5줄, 왜 중요한가, 투자 관점 한 줄 |
| **그림** | 원본 그림(잘라낸 PNG) · 캡션 · 출처 · *무엇을 보여주나* · *읽는 법*(축·단위·비교 대상) · *핵심 숫자* · *그래서?* |
| **표** | 데이터 표(정렬 가능) + 원본 이미지 토글 · 표에서 읽어야 할 것 2~3줄 |
| **개념** | 용어 풀이(비전공자 기준). 예: PD-1/PD-L1, ORR·PFS·OS·HR, TMB, ADC 페이로드·DAR, 1L/2L, 보조요법 |
| **임상** | 시험명 · 약 · 대조군 · 1차 평가변수 · 결과(HR, 개월) · 의미. 예: HARMONi-2/6, TroFuse-005, INTerpath-001, DeLLphi-304 |

모든 카드에 **원문 쪽번호**를 단다. 숫자는 원문 그대로 옮기고 내가 계산·추론한 값은 따로 표시한다.

### 1-4. 공통 색인 — 데이터가 쌓이는 곳

| 색인 | 예 | 연결 |
|---|---|---|
| 개념 | PD-1, ADC, TROP2, CDK4/6, C797S | 이 개념이 나온 모든 카드 |
| 약물 | 키트루다, 엔허투, 이보네시맙, 타그리소, 렉라자, VRN11 | 개발사, 타깃, 적응증, 매출(원문 표) |
| 기업 | Merck, AZ, 다이이찌산쿄, Summit, 보로노이, 유한양행, 알테오젠 | 국내 → 종목 상세 패널, 바이오 탭에 있으면 자산 카드 / 해외 → 티커 |
| 임상 | HARMONi-2, SAFFRON, DeLLphi-305 | 약물·적응증·결과 |

- **원문 내용**과 **내가 덧붙인 연결**(예: "키트루다 SC → 알테오젠 ALT-B4 기술")은 색과 표시로 구분한다. **[결정]** 덧붙임을 허용할지.

## 2. 파이프라인

```
PDF ──study_extract.py──▶ study_src/{doc}/        (원문 텍스트·쪽별 블록·그림/표 영역, 공개 안 함)
                          public/data/study/img/{doc}/fig-07.png ...
      (분해: 내가 원문을 읽고 카드 작성) ──▶ study/{sector}/{doc}.json   (손으로 고치는 원본, git 관리)
                                              study/entities.json        (개념·약물·기업 색인)
      build_study.py ──▶ public/data/study/index.json (트리·색인) + {doc}.json (카드)
```

- `study_extract.py <pdf> --sector bio --id hmsec-onc-vol1` : 캡션·`자료:` 위치로 그림 영역을 찾아 렌더(200dpi), 표는 데이터로, 쪽별 본문을 블록 단위로 저장. 그림·표 번호와 쪽번호 목록을 만들어 **빠진 그림이 없는지** 검사.
- 분해는 자동 요약이 아니라 **내가 원문을 장별로 읽고 카드로 쓰는 일**이다. 장 단위로 끊어 진행하고, 끝날 때마다 그림 수 = 카드 수를 대조한다.
- `build_study.py` : 카드 JSON 검증(쪽번호·그림 번호 중복/누락, 색인 키 존재) → 화면용 JSON. 기업 코드는 `names.json`, 바이오 탭 연결은 `bio_assets.json`에서 찾는다.
- PyMuPDF가 기본 파이썬에 없다 → `requirements.txt`에 `pymupdf` 추가.

## 3. 화면 (`study.html`)

- 왼쪽: 분류 트리 + 검색(카드 본문·색인 전체).
- 가운데: 주제 노트. 요약 카드 → 그림·표 카드가 원문 순서대로. 그림 카드는 왼쪽 이미지, 오른쪽 설명(좁은 화면에선 위아래).
- 오른쪽: 이 주제에 나온 개념·약물·기업 칩.
- 반도체·소비재는 트리만 있고 "아직 자료 없음".
- 기존 `app.css`·`util.js`·테마 그대로. 프레임워크 없음.

## 4. 공개 여부 — **[결정]** 로컬 전용 (권장)

이 대시보드는 `publish.py`로 GitHub Pages에 공개된다. 증권사 리포트의 그림과 문장을 잘라 올리면 저작권 문제가 될 수 있다.
→ `publish_hold.txt`에 `study.html`, `data/study` 를 넣어 **이 컴퓨터(`serve.py`)에서만** 본다. 공개가 필요하면 원문 그림을 뺀 공개용 사본을 따로 만든다(탐방 탭과 같은 방식).
